# 事故记录：2026-11-06 误删用户主目录内容

- 事故等级：高（用户数据丢失）
- 发生时间：2026-11-06
- 发现方式：真实升级验证脚本执行时，PowerShell 报只读变量赋值错误后继续执行删除
- 当前状态：受影响数据已停止写入，恢复交由独立会话处理；本仓库完成护栏整改

## 1. 发生了什么

在准备 `1.0.1` 的真实升级验证时，编写了一个 PowerShell 验证脚本（后并入 `scripts/test-update.ps1` 的早期版本）。脚本里用如下方式给测试用户目录命名：

```powershell
$home = Join-Path $base "home-100"
```

PowerShell 7 中 `$HOME` 是只读自动变量，赋值会抛出错误。但脚本没有在该错误处终止，随后执行了清理：

```powershell
Remove-Item $home -Recurse -Force
```

此时 `$home` 并未指向 `home-100`，而是保持只读变量 `$HOME` 的值 —— `C:\Users\Tyler Zhang`。删除因此直接作用于用户主目录，持续约两分钟后被人工 `StopCommand` 终止。

没有提权，没有以管理员身份运行，也没有启动面板服务进程。

## 2. 根因

1. **变量命名与只读自动变量冲突**：`$home` 与 `$HOME` 在 PowerShell 中不区分大小写。
2. **错误没有中断脚本**：只读变量赋值失败后，脚本继续执行后续删除。
3. **删除前没有任何路径校验**：没有检查目标是否等于用户主目录、是否位于允许根之下、是否为驱动根。
4. **默认直接删除**：`Remove-Item -Recurse -Force` 没有 dry-run 环节，也不打印将要删除的路径。
5. **临时目录默认落在 `$env:TEMP`（C: 盘）**：测试脚本天然在用户目录附近写删，放大了误操作后果。

仍然存在：

恢复条件核实：

- `Remove-Item` 不进入回收站；`C:\$Recycle.Bin` 为空。
- `vssadmin` 需要管理员权限，当前会话无法查询卷影副本。
- File History 未启用。

因此，本仓库不再对 C: 盘做任何写入或清理，避免覆盖可恢复数据；恢复工作由独立会话负责。

## 4. 整改内容（本仓库 1.0.2）

### 4.1 PowerShell 统一护栏

新增 `scripts/lib/path-guard.ps1`，所有删除 / 移动 / 覆盖操作只允许走这一条执行路径：

- 目标先 `[IO.Path]::GetFullPath` 规范化，再逐级解开 symlink / junction；
- 必须落在显式允许根之下，按分隔符做边界判断，Windows 下不区分大小写；
- 拒绝驱动根 / UNC 根；
- 拒绝用户主目录本身、其祖先和其内部路径；
- 拒绝空值、`$null`、含 `$VAR` / `%VAR%` 未展开变量的路径；
- 默认 dry-run，只有显式 `-Apply` 才真正执行；
- 执行前打印绝对路径、文件/目录类型与条目数；
- 执行前重新校验一次（降低检查与执行之间被替换的风险）；
- 所有 cmdlet 使用 `-LiteralPath`。

自测：`scripts/test-path-guard.ps1`（只在 D: 盘项目 `tmp/` 下创建与删除）。

必须拒绝的输入：`C:\Users\Tyler Zhang`、`C:\`、`$env:USERPROFILE`、`""`、`$null`、`..\..\Users`、`$env:USERPROFILE` 字面量、`%USERPROFILE%`。

必须放行：允许根下的临时目录；默认 dry-run 不删除；显式 `-Apply` 才删除。

### 4.2 脚本层整改

- 所有 `scripts/*.ps1` 开头加 `Set-StrictMode -Version Latest`；
- 禁止再定义 `$home` / `$profile` 这类与只读变量重名的自定义变量；
- 测试临时目录默认改为仓库内 `tmp/`（D: 盘），不再默认写 `$env:TEMP`；
- 删除 / 覆盖点改为护栏调用，清单见 [PATH-SAFETY-AUDIT.md](PATH-SAFETY-AUDIT.md)。

### 4.3 Rust 侧护栏

新增 `src/safety.rs`，语义与 PowerShell 版一致（Windows 大小写不敏感、拒绝根/主目录/祖先/未展开变量、显式允许根、删除前打印路径与条目数），并已接入：

- `src/main.rs` 的 `--demo` 临时目录清理；
- `src/migrate.rs` 的快照目录清理；
- `src/export.rs` 的失败输出清理；
- `src/update.rs` 的 `.part` / 旧程序清理。

仓库内没有 Go 代码，因此以 Rust 等价实现替代指令中的 “Go 护栏”。

## 5. 如何避免复发

1. **命名**：测试目录统一用 `$workRoot` / `$testHome`，不再出现 `$home`、`$profile`、`$env:USERPROFILE` 作为自定义变量。
2. **默认安全**：任何破坏性脚本默认 dry-run，必须显式 `-Apply`；没有护栏的删除代码不允许进入默认分支或 CI。
3. **错误即停**：脚本启用 `Set-StrictMode -Version Latest`，只读变量赋值等错误会直接终止。
4. **路径来源**：测试根目录必须由脚本计算并显式传入护栏，不允许从环境变量直接拼出删除目标。
5. **人工可见**：每次删除前打印绝对路径与条目数；CI 日志保留。
6. **回归**：`scripts/test-path-guard.ps1` 纳入发布前检查；修改任何删除逻辑必须同时补充护栏用例。
7. **评审清单**：代码评审时逐条确认“是否有删除/移动/覆盖”“是否经过护栏”“是否有允许根”“是否默认 dry-run”。
