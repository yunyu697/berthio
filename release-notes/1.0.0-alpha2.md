# Berthio 1.0.0-alpha2

第二个里程碑（M2）：规则集换源下载——内置官方源 + 多个可切换镜像，自动回退 / 手动指定，校验始终以官方 SHA-256 为准。

## 本里程碑包含

- **内置源清单**：`config/sources.json`，官方源（锁定）+ gh-proxy.com + ghproxy.net + jsDelivr CDN（默认启用）+ ghfast.top（2026-11 实测 403，默认禁用，保留作回退反例）。
- **自动回退**：无官方基准时官方先行（唯一能建立基准的来源）；已有基准时镜像优先、官方兜底；每一步都带耗时与状态。
- **手动指定**：界面可选「自动回退」或任一已启用源；手动模式只走指定源，失败即报错，不静默换源。
- **官方基准校验**：运行时以官方文件内容计算 SHA-256 写入 `data/rulesets/manifest.json`；镜像内容必须与最新基准一致才落盘，哈希不符/连接失败一律丢弃并继续回退，绝不覆盖已有缓存。
- **界面**：沿用设计稿，无版式重排；在「内核」页的「镜像源」卡片里可见源清单、启用开关、优先级、测速、拉取并校验、完整回退链与当前源（设计稿定版，卡片位置未移动）。
- **接口**：`GET/POST /api/rulesets/sources`、`PATCH/DELETE /api/rulesets/sources/<id>`、`PUT /api/rulesets/sources/mode`、`POST /api/rulesets/sources/test`、`POST /api/rulesets/fetch`。
- **回归脚本**：`scripts/test-m2-mirrors.ps1`（16 项断言，含错文件镜像、不可达镜像、无基准拒绝落盘、官方源不可删除等反例）。

## 本机实测（Windows，2026-11-06，真实网络）

同一时段两轮，均为 532 B 的 `geoip:private` 小文件（含 TLS 握手，不具大文件代表性）：

| 源 | 第一轮 | 第二轮 |
| --- | --- | --- |
| 官方 raw.githubusercontent.com | 795 ms | 960 ms |
| gh-proxy.com | 933 ms | 765 ms |
| cdn.jsdelivr.net | 504 ms | 1056 ms |

两条镜像均**真实下载成功且 SHA-256 与官方基准一致**。回归脚本 16/16 通过，关键反例：

- 把镜像指向别的文件（`geoip/cn.yaml`）→ 首步 `hash_mismatch`，被丢弃、未落盘，随后自动回退到 gh-proxy 并通过。
- 镜像指向不可达地址 → 首步 `transport` 失败，自动回退成功。
- 尚无官方基准时手动选镜像 → `no_baseline` 拒绝下载，提示先建立基准。
- 官方源删除 → 被拦截；禁用源手动选择 → 被拦截。

## 已知限制

- **只实测了小文件**：`geoip:private`、`geosite:youtube`；`geosite:cn` 等 2 MB 级大文件的镜像加速比尚未实测。
- **官方不可达且无基准时无法安装规则集**：这是刻意的安全边界（镜像不能自证），不做「镜像说了算」的降级。
- **基准会随上游更新**：官方内容变化时基准更新并写审计事件，旧缓存会被标「基准已更新」，需要重新拉取。
- **导出配置仍指向官方 URL**：镜像只加速本机规则文件下载，不改变生成配置里的 rule-provider 地址。
- **镜像列表是静态内置 + 手动添加**：没有在线源发现。
- **xray 仍未接入**：服务端 Reality 能力仍标「未验证」。
- **仅本机使用**：默认监听 `127.0.0.1:18080`，远程鉴权在 M3。

```bash
berthio --demo        # Windows: berthio.exe --demo
```
