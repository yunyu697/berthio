# Berthio 1.0.3-alpha2

本版补齐上一版自查发现的两个 S1 缺口，并加了一条契约测试防止同类问题复发。基线是 `1.0.3-alpha1`（内置 HTTPS、操作审计日志、入站修改/删除）。

## 本版内容

### 1. 入站客户端：新增 / 修改 / 停用 / 重置流量 / 删除

上一版只有「新增」接口且界面没有入口，客户端密钥泄露后无法止血。本版补齐：

- 界面：入站「编辑」弹窗内新增客户端区域，包含列表与「添加客户端」表单。
- 新增：`POST /api/inbound/inbounds/{id}/clients`，界面可对已有入站追加客户端，不再只能新建入站时随带一个。
- 修改：`PATCH /api/inbound/inbounds/{id}/clients/{cid}`，允许字段为 **email、配额（`quota_bytes`）、到期时间（`expires_at`，空字符串表示清空）、启用状态（`enabled`）、flow**。协议、安全层、UUID 不允许改——这些字段改动会破坏已导出的配置，重建入站比改更安全。
  - email 非空、≤64 字符、同一入站内唯一（409）；
  - 提交无实际变更返回 400。
- 停用 / 启用：走同一个 PATCH，`enabled=false/true`。界面停用需二次确认弹窗，写明「导出与订阅立即不可用，状态保留可随时启用」。
- 重置流量：`POST /api/inbound/inbounds/{id}/clients/{cid}/reset`，只把 `used_bytes` 归零，不动配额、到期与启用状态；界面有确认弹窗。
- 删除：`DELETE /api/inbound/inbounds/{id}/clients/{cid}?confirm={cid}`。
  - 界面弹窗二次确认，写明「只删除状态记录并重写 `state.json`、不删除任何文件」；
  - `confirm` 与客户端 id 不一致返回 400，且该次拒绝也写审计；
  - 只做 `clients.remove` + 原子重写 `state/state.json`，审计 detail 固定写 `files_deleted: 0`；
  - 不存在能作用到数据目录之外或用户主目录的删除路径。
- 审计事件：`inbound.client.created` / `inbound.client.updated` / `inbound.client.disabled` / `inbound.client.reset_traffic` / `inbound.client.deleted`。
  - 修改记录前后值（`changes`）；
  - 停用记录 `enabled: true → false`；
  - 重置记录 `previous_used_bytes`；
  - 删除记录被删客户端摘要：id、email、flow、配额、已用量、到期、启用、创建时间、`files_deleted`。

### 2. 订阅令牌：列表 / 轮换 / 吊销

上一版令牌只能在签发当次显示，刷新页面后无法再找到或处置。本版补齐：

- 新增 `GET /api/export/tokens`，返回令牌元信息：id、关联入站与客户端、email、target、状态（active/revoked）、创建时间、吊销时间、最后访问时间。
- **只存 SHA-256，列表不返回明文，也不返回 hash**；签发与轮换返回的新链接仅显示一次，刷新后不可再取。
- 导出页进入时自动加载令牌列表，可直接轮换或吊销；吊销为终态，不提供物理删除记录。
- 对已吊销令牌再次轮换返回 409。

### 3. 契约测试（防复发）

- 新增 [`docs/CAPABILITY-MATRIX.md`](../docs/CAPABILITY-MATRIX.md)：按实体声明「增/删/改/查」能力，逐项标注「必需 / 仅后端 / 有意不做」，有意不做必须写理由。
- 新增 `src/capability.rs`：同一份清单的机器可读声明表，加 4 个测试：
  1. 清单不得重复声明同一 `实体.动作`；
  2. 「有意不做」必须有理由且不得声明后端路由；
  3. `src/http.rs` 源码必须包含清单声明的每条路由分支；
  4. `web/app.js` 源码必须包含清单声明的每个前端调用。
- 测试直接扫描源码文本（`include_str!`），删掉真实路由或真实调用就会失败，不依赖人工记忆。

**反向验证（单独记录）**：

1. 临时把客户端删除路由的方法名从 `DELETE` 改为 `DELETE_TEMP_BROKEN`；
2. `cargo test capability` 报红，失败信息为：
   `inbound.client.delete 缺少后端路由探针：("DELETE", p) if p.starts_with("/api/inbound/inbounds/") && p.contains("/clients/")`
3. 恢复为 `DELETE`；
4. 同一命令转绿，4 个契约测试全部通过。

### 4. README 与实现对齐

入站管理一节改成与实现一致：入站编辑/删除、客户端新增/修改/停用/重置/删除均已声明。

## 实测数据（本地，D: 盘）

- 客户端修改：`email a@example.com → a2@example.com`、`quota 0 → 1048576`、`expires null → 2027-01-01T00:00:00Z`，`changes` 与列表回读一致。
- 重名冲突：409；删除 confirm 不匹配：400。
- 停用：`enabled true → false`，回读为 false；重新启用成功。
- 重置流量：`reset=true`，`previous_used_bytes=0`（测试环境没有真实流量增长）。
- 删除客户端：成功，`remaining_clients=1`，摘要含 `files_deleted: 0`；数据目录文件数删除前后均为 5，`files_delta: 0`。
- 令牌列表：`list_contains_plaintext=false`、`list_contains_hash_key=false`；轮换返回新 token，列表不含新 token 也不含旧 token；吊销后 `status=revoked`；对已吊销令牌轮换返回 409。
- 审计：`action=inbound` 命中 8 条，含 `created / updated / disabled / reset_traffic / deleted` 全链路。
- `cargo test`：23 项全部通过（含 4 项契约测试、auditlog、tls、safety、update、auth）。

## 已知差距（照原样保留）

- **更新流程未实跑**：审计对更新链路的覆盖只做了代码接线，没有在本轮用真实更新流程逐条核对审计事件。
- **`export.download` 成功路径未实测**：只验证了拒绝路径（校验 FAIL 时写 `denied`），成功下载的审计记录没有实跑确认。
- **日志页筛选未在真实浏览器点验**：筛选与 CSV 导出只做了接口与语法检查，没有在浏览器里逐项点击验证。
- **HTTPS 的 Windows 权限**：私钥 0600 是 Unix 权限位，Windows 上不生效。
- **TLS 变更需重启**：证书、私钥、明文策略变更后需重启进程生效。
- **没有 ACME**：只支持手动 PEM 或自签。
- **`strict` 返回 403**：不做 HTTP → HTTPS 跳转。
- **入站与客户端编辑范围有限**：入站只改备注/监听/端口/启用；客户端只改 email/配额/到期/启用/flow，协议与安全层不可改。
- **没有面板数据备份/恢复**：只有升级前自动备份；计划在 `1.0.3-alpha3` 补齐。
- **证书不能删除**：只能停用后手动删文件；计划在 `1.0.3-alpha3` 补齐并走 `src/safety.rs`。
- **没有退出登录按钮**：`POST /api/auth/logout` 可用，但界面未放入口，需清 Cookie 或等会话过期。

## 升级

从 `1.0.3-alpha1`：设置页「检查更新」→「更新」→ 下载 → 校验 → 替换 → 自动重启。明文策略仍默认 `warn`，升级后行为不变。
