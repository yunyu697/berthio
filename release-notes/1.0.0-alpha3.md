# Berthio 1.0.0-alpha3

M3：远程访问鉴权 + 内核进程管理。**alpha 版本，未签名，不建议生产使用。**

## 本版内容

### 1. 远程访问鉴权

- **首次启动初始化**：无 `state/auth.json` 时前端强制设置管理员口令；口令只以 PBKDF2-HMAC-SHA256（随机 16 字节盐、120,000 次迭代）哈希落盘，明文不进磁盘、不进日志、不进审计。
- **会话**：32 字节随机令牌，Cookie `berthio_session` 带 `HttpOnly` / `SameSite=Strict` / `Path=/` / `Max-Age`；HTTPS 下追加 `Secure`。有效期默认 12h（`BERTHIO_SESSION_TTL_SECS`），到期自动失效。
- **CSRF**：独立的 `csrf_token`，所有写操作（含 API 路由）必须带 `X-Berthio-CSRF`，缺失/错误分别返回 `csrf_required` / `csrf_invalid`。
- **登录限速**：按客户端 IP 计数，默认 5 次失败锁定 300 s（`BERTHIO_LOGIN_MAX_FAILS` / `BERTHIO_LOGIN_LOCK_SECS`）；锁定期内正确口令也返回 429。
- **注销与改密**：可主动注销；改口令会吊销全部会话。
- **监听安全**：默认且强制回环 `127.0.0.1`；开启远程监听必须同时提交 `confirm_remote=ENABLE-REMOTE`，否则 400 并返回风险清单；成功写入确认时间/操作者并要求重启。
- **反代**：默认完全不信任 `X-Forwarded-For`（以 peer IP 为准）；只有 peer 在 `trusted_proxies` 内或显式 `BERTHIO_TRUST_PROXY=1` 时才解析，并从右向左跳过受信代理；`X-Forwarded-Proto=https` 决定 Cookie 是否加 `Secure`。
- **鉴权覆盖面**：`/`、`/app.js`、`/favicon.ico`、`/healthz`、`/api/auth/status|setup|login`、订阅路径之外的所有 `/api/*` 均要求有效会话，写方法再校验 CSRF。

### 2. 内核进程管理（xray / sing-box / mihomo）

- **启动前检查**（顺序固定）：渲染配置 → 特权端口检查 → 端口占用检测 → 二进制配置自检（`xray -test -config` / `sing-box check -c` / `mihomo -t -f`）→ spawn → 1.2 s 存活确认。
- **失败处理**：自检失败返回 422 `config_check_failed` 并附具体命令与二进制输出，不启动；未安装二进制返回 422 `binary_missing`。
- **端口冲突**：启动前实际 bind 试占，失败返回 409 `port_in_use`，并给出占用者 `owner{name,pid,source}`（Windows 用 `Get-NetTCPConnection` + `Get-Process`，Linux 用 `ss -lntup`）。
- **状态持久化**：`state/kernels.json` 原子落盘 status/pid/restarts/last_error/alert/rolled_back_to/adopted/log_path 等；面板重启后按 pid + 命令行核验接管（`adopted=true`），不重启进程。
- **孤儿清理**：状态文件缺失或无记录时，仅清理命令行包含本面板 `configs/generated` 路径的内核进程，其他进程不动。
- **自动拉起**：异常退出默认最多 3 次，超限置 `failed` + 告警（审计 `kernel.alert`）；手动 start 重置计数。
- **失败回滚**：每次成功启动保存 `state/kernels/<kernel>.lkg`；自检/spawn/早退失败时回写该配置，状态记 `rolled_back_to`，不留「起不来又没退路」。
- **日志**：stdout/stderr 落 `logs/kernels/<kernel>.log`，启动前按 `BERTHIO_KERNEL_LOG_MAX`（字节，默认 5 MB）轮转 `.log.1/.2/.3`；`GET /api/kernels/<k>/log?tail=N` 查看尾部。
- **权限**：Unix 下绑定 <1024 端口且非 root 时返回 409 `privilege_required` 并列出具体绑定操作，不调用 sudo、不在后台提权。
- **demo**：`Supervisor` 处于 demo 状态，任何启停/校验返回 409 `demo_mode`，**绝不启动真实内核**。

### 3. 前端

- 新增登录/初始化遮罩；所有写操作自动带 CSRF；401 自动回到登录页。
- 「内核」页新增进程管理卡片：状态、PID、端口、启动/停止/重启/校验/日志，端口冲突与校验失败直接展示具体原因。
- 设置页：口令修改、监听地址/端口、受信反代、远程监听风险确认与一键恢复回环。

## 实测结果（Windows 10/11，真实二进制）

| 项目 | 结果 |
|---|---|
| xray 配置自检 | `xray -test -config` 通过（"Configuration OK."），真实启动并监听配置端口 |
| 端口冲突 | 预先占用 29443 后启动返回 409，`owner` 指出占用进程 PID 与名称（pwsh，脚本断言） |
| 配置校验失败 | 把 Reality 私钥改为非法值后启动返回 422 `config_check_failed`，带 xray 具体报错；生成配置 SHA-256 等于 `.lkg`，进程未启动 |
| 自动拉起 | 外部强制结束进程：第 1 次 3 s 内 `running/restarts=1`；连续第 4 次后 `failed` + `alert`，`restarts=3`；手动 start 重置为 0 |
| 面板重启接管 | 强制结束面板后重启：`adopted=true`、pid 不变、内核继续监听 |
| 孤儿清理 | 结束面板、删除 `state/kernels.json` 后重启：残留 xray 被清理，无孤儿 |
| 日志轮转 | 预置 1.3 MB `xray.log`、阈值 1 MB：启动后生成 `xray.log.1`，新日志从 0 开始 |
| sing-box | `sing-box check` 通过；真实启动并监听 29444（手工一轮） |
| mihomo | `mihomo -t` 通过；真实启动/停止（手工一轮） |
| 鉴权 | 29 项脚本断言全部通过：初始化、哈希存储、Cookie 属性、401/403/429、伪造 XFF、会话过期、注销、改密、远程确认 |
| 内核 | 25 项脚本断言全部通过（含 xray 全生命周期与 mihomo/sing-box 配置校验） |
| demo | `--demo` 下 `auth` 全通过、`runtime` 全为 `demo`、start 返回 409，系统中无真实内核进程 |

复跑方式（PowerShell 7，`pwsh`；5.1 会自动切换）：

```powershell
pwsh -File scripts/test-m3-auth.ps1 -Exe .\target\release\berthio.exe -Port 18185
pwsh -File scripts/test-m3-kernels.ps1 -Exe .\target\release\berthio.exe -KernelDir .\.tools\kernel -Port 18186 -InboundPort 29512
```

## 未验证 / 已知限制

- **Linux 侧未实测**：特权端口（<1024）的 `privilege_required` 分支与 `ss -lntup` 解析只在代码/单测层面验证，本轮实机为 Windows，未触发该分支。
- **真实反代未实测**：仅验证「不配置受信代理时伪造 XFF 被忽略」；受信代理白名单与 `X-Forwarded-Proto=https` 的 Cookie `Secure` 行为未接入真实 nginx 验证。
- **会话与锁定状态只在内存**：面板重启后需重新登录，失败计数清零（有意为之）。
- **自动拉起为固定 500 ms 间隔**，无指数退避；`restart_limit` 暂不可按内核单独配置。
- **mihomo 运行配置为最小直连模式**（无监听端口），只用于进程管理/校验演示，不承担实际入站。
- **Windows 下 `owner` 依赖 `Get-NetTCPConnection`**，个别系统上状态列不可靠，已改用只查端口 + `Get-Process`，极端情况可能 `known=false`。
- **Docker 部署不在 M3 范围**（Q8 仍待拍板）。
- 本 alpha 未签名；发布附件为 Linux 构建，Windows 下请按 `scripts/test-m3-*.ps1` 自测。
