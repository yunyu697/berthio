# Berthio 1.0.3

本版为 1.0.3 正式版，合并 `1.0.3-alpha1` / `1.0.3-alpha2` / `1.0.3-alpha3` 三批改动，并完成能力清单与契约测试的最终对齐。三批改动此前只在本地实跑过，正式版沿用同一套代码，仅版本号与发布说明合并。

## 本版内容

### 1. 入站修改与删除

- 入站列表行新增「编辑」「删除」入口。
- 编辑只允许改四类字段：备注、监听地址、端口、启用状态。
  - 备注非空且不超过 64 字符，不得与其他入站重名（409）；
  - 端口不能为 0；与其他入站 `listen + port + l4` 冲突时返回 409；端口被系统占用时返回 409；
  - 提交没有任何实际变更时返回 400「没有需要修改的字段」；
  - 协议、安全层、传输、客户端不在编辑范围。
- 删除必须二次确认：`DELETE /api/inbound/inbounds/<id>?confirm=<id>`，`confirm` 与 `id` 不一致返回 400，且该次拒绝也写审计。
- 删除只从内存状态移除并原子重写 `state/state.json`，**不调用任何文件删除 API**，审计 detail 固定写 `files_deleted: 0`。
- 审计：`inbound.updated` / `inbound.deleted`，成功记改动前后值或删除摘要，失败记 `denied` 与原因。

### 2. 入站客户端：新增 / 修改 / 停用 / 重置流量 / 删除

- 界面：入站「编辑」弹窗内新增客户端区域，含列表与「添加客户端」表单。
- 新增 `POST /api/inbound/inbounds/{id}/clients`。
- 修改 `PATCH /api/inbound/inbounds/{id}/clients/{cid}`，允许字段为 **email、配额（`quota_bytes`）、到期时间（`expires_at`，空字符串表示清空）、启用状态（`enabled`）、flow**；协议、安全层、UUID 不允许改。
  - email 非空、≤64 字符、同一入站内唯一（409）；无实际变更返回 400。
- 停用 / 启用走同一个 PATCH（`enabled=false/true`），界面停用需二次确认。
- 重置流量 `POST .../clients/{cid}/reset`，只把 `used_bytes` 归零，不动配额、到期与启用状态。
- 删除 `DELETE .../clients/{cid}?confirm={cid}`：`confirm` 不一致返回 400 并写审计；只做 `clients.remove` + 原子重写 `state.json`，`files_deleted: 0`。
- 审计：`inbound.client.created` / `updated` / `disabled` / `reset_traffic` / `deleted`。

### 3. 订阅令牌：列表 / 轮换 / 吊销

- 新增 `GET /api/export/tokens`，返回 id、关联入站与客户端、email、target、状态、创建时间、吊销时间、最后访问时间。
- **只存 SHA-256；列表既不返回明文也不返回 hash**；签发与轮换返回的新链接仅显示一次。
- 导出页进入时自动加载列表，可直接轮换或吊销；吊销为终态，不提供物理删除。
- 对已吊销令牌再次轮换返回 409。

### 4. 内置 HTTPS 与明文策略

- 可配置 PEM 证书与私钥路径，支持一键自签；自签 SAN 覆盖 `localhost`、`127.0.0.1`、`::1` 与本机全部网卡地址；面板显示指纹与到期时间，临期写日志告警。
- 明文策略三档 `warn` / `loopback-only` / `strict`：**默认 `warn`，升级后行为不变**；`loopback-only` 只放行回环明文，非回环返回 403；`strict` 一律拒绝明文并返回 403（不做 302 跳转）。
- 只有配置了可信代理 CIDR 时才采信 `X-Forwarded-Proto` / `X-Forwarded-For`。
- TLS 生效时统一加 HSTS；Cookie 加 `Secure` 与 `SameSite`。

### 5. 操作审计日志

- 只追加 JSONL，按月归档（`logs/audit/YYYY-MM.jsonl`），单文件超过 8 MB 轮转，保留 `log_keep_days`（默认 14）天，24 小时最多清理一次。
- 字段：时间、操作者、来源 IP、动作、目标、结果、详情。
- 覆盖：登录成功/失败、面板口令初始化与修改、入站增/改/删、客户端增/改/停用/重置/删、3x-ui 数据库与 JSON 导入、更新检查/下载/安装、内核启动/停止/重启/校验、配置导出、TLS 自签与删除、备份创建/恢复、面板设置变更。
- 脱敏：写入前递归处理 detail，键名含 `password` / `passwd` / `secret` / `token` / `private` / `credential` / `uuid` / `cookie` / `authorization` / `subscription_url` 的值，或键名为 `key` / 以 `key` 结尾且不是 `_path` 的值，统一替换为 `[redacted]`；`_id` / `_path` / `id` 豁免。
- 日志页支持按时间范围、操作者、动作、结果、关键字筛选；CSV 导出带 BOM，并对以 `= + - @` 开头的单元格做公式注入防护。
- 写失败不影响业务；`/healthz` 暴露写入失败次数与最后错误。没有删除或清空接口。

### 6. 证书删除：`DELETE /api/tls/cert?confirm=delete`

- 前置条件：内置 TLS 未启用（配置与运行态任一启用都拒绝，409），避免重启后起不来。
- 二次确认：`confirm` 必须为 `delete`，不匹配返回 400 并写审计。
- 路径护栏：证书与私钥都先过 [`src/safety.rs`](../src/safety.rs) 干跑校验，目标必须在数据目录内；任一越界则整体拒绝，一个文件都不删。
- 删除前记录证书指纹与到期时间；审计 `tls.deleted`，拒绝记 `reason`（`confirm_mismatch` / `tls_enabled` / `outside_data_dir`）。
- 删除后配置里的路径保留，可重新生成或改用外部证书后再启用 TLS。

### 7. 面板数据主动备份 / 恢复

- `GET /api/backup`：返回包含文件清单（相对路径、用途、字节数）、明确排除项及理由、已有备份列表。
- `POST /api/backup`：写入 `state/backups/manual-<时间戳>-<随机>/`（`manifest.json` + `files/`），每文件写入后回读校验 SHA-256；审计 `backup.created`。
- `POST /api/backup/restore`：`confirm` 等于备份名 → 校验清单 `kind` / `schema` → 先把所有文件读入内存逐个核对 SHA-256（失败在改动现场之前返回 400）→ 拍 `prerestore-*` 回滚快照 → 逐文件原子替换 → 任一步失败按逆序回滚；审计 `backup.restored`。
- 纳入备份：`config/panel.json`、`config/sources.json`、`state/state.json`、`state/auth.json`，以及相对路径配置的内置 TLS 证书/私钥。
- 明确排除：`logs/audit/*`、`state/kernels.json`、`state/update.json`、`state/backups/*`、内核日志、规则/Geo 缓存、`configs/generated/*`、`tmp/*`；绝对路径的证书/私钥不猜测、不越界复制，清单中标注未纳入。
- 界面「数据目录与备份」为真实功能：显示数据根目录、逐项列出包含与排除理由、列出已有备份、可「立即备份」与「恢复」，恢复后提示需重启。

### 8. 能力清单与契约测试

  2. **`panel.user.logout`**：级别为「仅后端」（`POST /api/auth/logout` 可用，界面无入口）；
  3. **备份排除项**：把「审计日志 / 运行态文件纳入备份」登记为「有意不做」并写理由，不再靠遗漏表达。

## 升级

## 已知差距

以下为当前明确未覆盖或有意保留的边界，集中列出，不作模糊表述：

1. **恢复不是跨文件事务**：`config/` 与 `state/` 下的文件无法作为整体原子替换。写入失败会按逆序自动回滚，但若进程在恢复过程中被强制杀死，仍可能留下部分文件已替换的状态，需从 `prerestore-*` 快照人工恢复。
2. **恢复后必须重启**：文件已替换，但运行进程内存中仍是旧配置，界面会提示重启生效。
3. **Windows 下 0600 不生效**：私钥权限 0600 是 Unix 权限位，Windows 上只能依赖数据目录本身的访问控制。
4. **更新流程审计未逐条实跑**：更新链路的审计覆盖只做了代码接线，没有用真实更新流程逐条核对每条审计事件。
5. **`export.download` 成功路径未实测**：只验证了拒绝路径（校验 FAIL 时写 `denied`），成功下载的审计记录未实跑确认。
6. **日志页筛选未在真实浏览器点验**：筛选与 CSV 导出只做了接口与语法检查，未在浏览器里逐项点击验证。
7. **没有 ACME**：不自动申请公网证书，只支持手动 PEM 或自签。
8. **`strict` 返回 403**：不做 HTTP → HTTPS 跳转，避免误导 API 客户端。
9. **入站与客户端可改字段有限**：入站只改备注/监听/端口/启用；客户端只改 email/配额/到期/启用/flow；协议、安全层、UUID 不可改。
10. **没有退出登录按钮**：`POST /api/auth/logout` 可用，但界面未放入口，需清 Cookie 或等会话过期。

附加边界：

- **备份不含审计日志**：审计只追加，不参与覆盖式恢复（有意选择，不是遗漏）。
- **TLS 变更需重启**：证书、私钥、明文策略变更后需重启进程生效，面板会提示但不自动重启。
- **未做系统级代码签名**：Windows 可能提示来源不明；更新包由 minisign 清单签名并以公钥校验，与系统代码签名是不同层面的机制。
