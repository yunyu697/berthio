# Berthio 1.0.3-alpha1

本版是 alpha，新增三项能力：内置 HTTPS、操作审计日志、入站修改与删除。三项都只在本地实测过，按 alpha 先小范围验证。

## 本版内容

### 1. 入站修改与删除

- 入站列表行新增「编辑」「删除」两个入口。
- 编辑只允许改四类字段：备注、监听地址、端口、启用状态。
  - 备注非空且不超过 64 字符，不得与其他入站重名（409）；
  - 端口不能为 0；与其他入站 `listen + port + l4` 冲突时返回 409；端口被系统占用时返回 409；
  - 提交没有任何实际变更时返回 400「没有需要修改的字段」。
  - 协议、安全层、传输、客户端不在编辑范围，避免改坏已导出的配置。
- 删除必须二次确认：
  - 前端弹窗明确列出将删除的入站、端口与客户端数量，并写明「只删除状态记录、不删除任何文件、会写入审计日志」；
  - 后端强制 `DELETE /api/inbound/inbounds/<id>?confirm=<id>`，`confirm` 与 `id` 不一致直接 400，且该次拒绝也写审计。
- 删除只做两件事：从内存状态移除该入站，原子重写 `state/state.json`。
  - **不调用任何文件删除 API**，审计 detail 中固定写 `files_deleted: 0`；
  - 不存在能作用到数据目录之外或用户主目录的删除路径；
  - 入站 `tag` 是稳定标识，改端口不会重命名 tag。
- 审计事件：`inbound.updated` / `inbound.deleted`。成功记录改动前后值（`changes`）或删除摘要（id、tag、remark、协议、网络、安全层、监听、端口、l4、内核、客户端数、来源、创建时间、`files_deleted`）；失败记录 `denied` 与原因。

### 2. 内置 HTTPS

- 可配置 PEM 证书与私钥路径；支持一键自签证书。
  - 自签 SAN 覆盖 `localhost`、`127.0.0.1`、`::1` 与本机全部网卡地址；
  - 私钥写入数据目录，Linux 下权限 0600；
  - 面板显示证书指纹与到期时间；
  - 证书临期会写日志告警。
- 明文策略三档：`warn` / `loopback-only` / `strict`。
  - **默认 `warn`，升级后行为不变**：现有明文访问照常可用，只记录提示，不拦截。
  - 切到 `loopback-only`：只有回环地址的明文访问放行，非回环明文返回 403。
  - 切到 `strict`：一律拒绝明文，返回 403（不是 302 跳转，避免 API 客户端被误导）。
  - 切换方式：设置页「明文策略」，或 `PATCH /api/panel` 提交 `{"plain_policy":"loopback-only"}` / `{"plain_policy":"strict"}`；TLS 相关变更需重启进程生效。
- 反向代理：只有配置了可信代理 CIDR 时，才采信 `X-Forwarded-Proto` / `X-Forwarded-For`；否则按直连地址判定。
- TLS 生效时统一加 HSTS；Cookie 加 `Secure` 与 `SameSite`。
- 不破坏现有配置：未开启 TLS 时仍按原明文方式启动，`config/panel.json` 只增加字段、不改变原值语义。

### 3. 操作审计日志

- 只追加 JSONL，按月归档（`logs/audit/YYYY-MM.jsonl`）；单文件超过 8 MB 轮转为 `YYYY-MM.rot-HHMMSS-n.jsonl`。
- 保留天数取 `log_keep_days`（默认 14），每次写入节流触发清理，24 小时最多一次；只删本目录内符合命名规则的普通文件。
- 字段：时间、操作者、来源 IP、动作、目标、结果、详情。
- 覆盖：登录成功/失败、面板口令初始化与修改、入站增/改/删、客户端新增、3x-ui 数据库与 JSON 导入、更新检查/下载/安装、内核启动/停止/重启/校验、配置导出、TLS 自签、面板设置变更。
- 脱敏：写入前递归处理 detail，键名含 `password` / `passwd` / `secret` / `token` / `private` / `credential` / `uuid` / `cookie` / `authorization` / `subscription_url` 的值，或键名为 `key` / 以 `key` 结尾且不是 `_path` 的值，统一替换为 `[redacted]`；`_id` / `_path` / `id` 豁免。
- 日志页支持按时间范围、操作者、动作、结果、关键字筛选；CSV 导出带 BOM，并对以 `= + - @` 开头的单元格做公式注入防护。
- 写失败不影响业务：单次写入失败只增加失败计数并记录最后错误，业务请求照常完成；`/healthz` 暴露写入失败次数与最后错误。
- 没有删除或清空接口，也没有对应界面入口。

## 已知差距（如实保留）

- **更新流程未实跑**：审计对更新链路的覆盖只做了代码接线，没有在本轮用真实更新流程逐条核对审计事件。
- **`export.download` 成功路径未实测**：只验证了拒绝路径（校验 FAIL 时写 `denied`），成功下载的审计记录没有实跑确认。
- **日志页筛选未在真实浏览器点验**：筛选与 CSV 导出只做了接口与语法检查，没有在浏览器里逐项点击验证。
- **HTTPS 的 Windows 权限**：私钥 0600 是 Unix 权限位，Windows 上不生效，只能依赖数据目录本身的访问控制。
- **TLS 变更需重启**：证书、私钥、明文策略变更后需重启进程才生效，面板会提示但不自动重启。
- **没有 ACME**：不自动申请公网证书，只支持手动 PEM 或自签。
- **`strict` 返回 403**：不做 HTTP → HTTPS 跳转。
- **入站编辑范围有限**：只能改备注/监听/端口/启用；协议、安全层、传输、客户端仍不能编辑。
- **客户端管理仍不完整**：目前只有新增与查看，没有修改、删除、禁用、重置流量的接口与界面；订阅令牌只能在本会话内轮换/吊销，刷新后没有列表可查。
- **未做系统级代码签名**：Windows 可能提示来源不明；更新包由 minisign 清单签名并以公钥校验，这与系统代码签名是不同层面的机制。

## 升级

从 1.0.2 升级：设置页「检查更新」→ 发现 1.0.3-alpha1 → 「更新」→ 下载 → 校验 → 替换 → 进程退出 → 自动重启。1.0.2 已具备更新入口，可以走真实自更新。

明文策略默认 `warn`，因此升级后访问方式与行为不变；需要收紧时再手动切 `loopback-only` 或 `strict`。

## 校验

`SHA256SUMS` 随附件发布，Linux 可用 `sha256sum -c SHA256SUMS` 校验；两个二进制的 `--version` 均为 `berthio 1.0.3-alpha1`，tag 与 `Cargo.toml` 版本一致。
