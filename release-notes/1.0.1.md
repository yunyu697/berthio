# Berthio 1.0.1

本版只做三件事：设置页自更新交互、补一份中文 README、修掉自更新下载成功后的临时文件残留。不含新的入站类型或内核能力。

## 本版内容

1. **自更新交互**（设置页）
   - 未检查时只有「检查更新」与「打开主页」；检查中按钮禁用并显示进度。
   - 只有发现新版本时才出现「更新」和「仅下载」，同时显示版本号、包大小、来源；已是最新时这两个按钮不出现。
   - 「更新」：下载 → 完整性校验 → 替换当前可执行文件 → 进程退出 → 自动重启。
   - 「仅下载」：保存到默认下载目录，完成后按钮变「安装」；已下载且校验通过的包，即使随后版本已是最新，仍保留「安装」入口。
   - 多源逐源尝试（所选镜像 → 官方 → 其余镜像；自动模式为官方 → 其余镜像），失败原因按源逐条展示，可重试或换源。
   - 完整性校验 fail-closed：使用内嵌 minisign 公钥（可用 `config/panel.json` 覆盖），没有可用公钥即拒绝安装，不提供「跳过校验」。
   - 下载先写 `.part`，失败或换源即删，启动时清理残留；安装前再次校验大小、SHA-256 与签名。
2. **中文 README**：项目定位、主要能力、`--demo` 快速开始、安装方式、配置与状态文件位置、版本号规则、已知限制与反馈渠道。
3. **修复 `.part` 残留**：`仅下载` 成功后临时文件未删除，会在 `tmp/update/` 留下残片；本版改为落盘后立即删除。

## 已知限制与未验证项

- **从 1.0.0 升级到 1.0.1 需要手动替换一次**：1.0.0 发布时还没有更新入口（其发布说明也写明「本版未实现」），因此无法由 1.0.0 自己检查并升级。手动替换到 1.0.1 后，后续版本才能走自更新。
- **Linux 真实替换未实跑**：Linux 的替换/重启代码路径已实现，但本机验收只在 Windows 上完成了真实替换与自动重启。
- **未做系统级代码签名**：Windows 可能提示来源不明；更新包由 minisign 清单签名并以公钥校验，这与系统代码签名是不同层面的机制。
- **面板不带内置 HTTPS**：默认只监听 `127.0.0.1`；对外提供服务需要自行加反向代理、HTTPS 与强口令。
- 其余限制与 1.0.0 相同：hysteria2 入站未验证、mihomo 普通 Reality 未复测、xhttp 仅 xray 客户端、单实例单数据目录。详见 README 的「已知限制与未验证项」。

## 验证

本版实现后的自测（详细口径见 README 与 `scripts/test-update.ps1`）：

- 单元测试 10 项通过（其中更新专项 7 项：版本规则、签名有效/篡改/换公钥/版本不符/文件名不符、无公钥拒绝、候选顺序、`.part` 清理、状态回读、文件名清洗）。
- 离线源 API 验收 22 项通过：已最新、发现新版本、错包拒收、下载中断清理、镜像失败自动回退、逐源错误、仅下载落盘、重启后保留记录。
- 无头 UI 验收 14 项通过（`--headless=new`）：未检查只有两个入口、发现新版本才出现两个按钮、已最新时按钮消失、仅下载后变「安装」、已最新仍保留安装、打开主页始终在、镜像失败逐源展示并回退、无 JS 错误。
- 真实替换重启 4 项通过：在 Windows 上用当前二进制复制并签成 1.0.1 的夹具包，验证了替换、旧进程退出、新进程接管与 `last_install.restarted_at` 写入。该测试验证的是替换链路，不是已发布 1.0.0 到 1.0.1 的真实升级。

## 安装与升级

附件与 1.0.0 相同：Linux 二进制、Windows 二进制、demo 页面与 `SHA256SUMS`。Linux 二进制以 Debian 12（glibc 2.36）为基线。

从 1.0.0 手动升级：

1. 停止 1.0.0 进程，保留数据目录（默认 `./.berthio`，或 `BERTHIO_HOME` 指定位置）。
2. 用 1.0.1 的二进制替换原可执行文件，重新启动。
3. 打开设置页「检查更新」，确认入口可用；后续版本可直接走「更新」。

## 校验

`SHA256SUMS` 随附件发布，Linux 可用 `sha256sum -c SHA256SUMS` 校验；两个二进制的 `--version` 均为 `berthio 1.0.1`，tag 与 `Cargo.toml` 版本一致。
