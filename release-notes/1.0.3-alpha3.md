# Berthio 1.0.3-alpha3

本版补上两个 S2 缺口：证书删除、面板数据主动备份/恢复。基线是 `1.0.3-alpha2`（客户端增删改停用重置、订阅令牌列表、契约测试）。

## 本版内容

### 1. 证书删除：`DELETE /api/tls/cert?confirm=delete`

- 前置条件：内置 TLS 未启用（配置与运行态任一启用都拒绝，409），避免重启后因缺证书起不来。界面提示先关闭「内置 TLS」并保存。
- 二次确认：`confirm` 必须为 `delete`，不匹配返回 400，且该次拒绝也写审计。
- 路径护栏：证书与私钥两个目标都先过 [`src/safety.rs`](../src/safety.rs) 的干跑校验，目标必须位于数据目录内；任一越界则整体拒绝（400），**一个文件都不删**。不存在能作用到数据目录之外或用户主目录的删除路径。
- 删除对象：配置里的证书与私钥（默认 `config/tls/panel.crt` / `panel.key`），去重后逐个删除；删除前记录证书指纹与到期时间。
- 审计 `tls.deleted`：成功记 `files`、`files_deleted`、`cert_fingerprint`、`not_after`；拒绝记 `reason`（`confirm_mismatch` / `tls_enabled` / `outside_data_dir`）。
- 界面：设置页 TLS 卡片新增「删除证书」，弹窗写明删除范围、护栏与审计；删除后配置里的路径保留，可重新生成或改用外部证书后再启用 TLS。

### 2. 面板数据主动备份 / 恢复

- `GET /api/backup`：返回「包含哪些文件」（相对路径、用途、字节数）、「明确排除哪些及理由」，以及已有备份列表（名称、类型、文件数、字节数、版本、是否可恢复）。
- `POST /api/backup`：在 `state/backups/manual-<时间戳>-<随机>/` 下落 `manifest.json` + `files/`（按相对路径存放）。每个文件写入后回读校验 SHA-256；审计 `backup.created`（文件数、总字节、路径）。
- `POST /api/backup/restore`：
  1. `confirm` 必须等于备份名；
  2. 校验清单 `kind` / `schema`，`schema` 高于当前支持版本直接拒绝；
  3. **先把所有文件读入内存并逐个核对 SHA-256**，任何一项失败都在改动现场之前返回 400；
  4. 给本次会被覆盖的文件拍 `state/backups/prerestore-*` 回滚快照；
  5. 逐文件原子替换（同目录临时文件 + 重命名）；任一写入失败按逆序自动回滚已写入的文件；
  6. 审计 `backup.restored`（成功记恢复文件数、回滚快照；失败记 `denied` 与原因）。
- 纳入备份：`config/panel.json`、`config/sources.json`、`state/state.json`、`state/auth.json`，以及**相对路径**配置的内置 TLS 证书/私钥。
- 明确不纳入并写明理由：`logs/audit/*`（审计只追加，不参与覆盖式恢复）、`state/kernels.json`、`state/update.json`（运行态）、`state/backups/*`（避免递归）、内核日志、规则/Geo 缓存、`configs/generated/*`、`tmp/*`。证书/私钥若配置为绝对路径，不猜测、不越界复制，在清单里标为未纳入。
- 界面：设置页「数据目录与备份」改为真实功能——显示数据根目录、逐项列出包含与排除理由、列出已有备份、可「立即备份」与「恢复」。恢复弹窗列出将被覆盖的文件，二次确认；恢复后提示需重启生效。

### 3. 契约清单同步

- [`docs/CAPABILITY-MATRIX.md`](../docs/CAPABILITY-MATRIX.md) 与 `src/capability.rs` 中 `tls.delete`、`backup.list/create/restore` 由「有意不做」改为「必需」，并补后端路由与前端调用探针。
- 「审计日志 / 运行态文件纳入备份」登记为「有意不做」并写理由，不再靠遗漏表达。

## 实测数据（本地，D: 盘，端口 18178/18179）

- 证书生成后删除流程：
  - `confirm=wrong` → 400，证书与私钥均仍在；
  - 把 `tls_cert` / `tls_key` 指向数据目录外的绝对路径 → 删除返回 400（`目标不在允许根之下`），目录外两个文件与数据目录内证书均未删；
  - 恢复正常：`files_deleted=2`（`panel.crt`、`panel.key`），审计记录指纹 `9F:C8:98:49:…:31:5A:F9`；
  - 审计 `tls.deleted` 共 6 条（含 confirm 拒绝、越界拒绝、成功删除）。
- 备份 / 恢复：
  - 首次备份 `manual-1794007114-c26bf8`，3 个文件、1262 字节（本次 `sources.json` 未配置、证书已删；正常部署含来源与 TLS 时为 5–6 个）；
  - 清单列出 9 项排除及理由；
  - 篡改备份内 `state/state.json` 后恢复 → 400（`备份文件校验失败`），现场 `state.json` SHA-256 与篡改前一致；
  - 正常恢复 `restored=3`，`state.json` SHA-256 回到备份值；回滚快照 `state/backups/prerestore-1794007115-8139ca` 已生成；
  - 新实例（独立数据目录）恢复成功，`panel.json` 与 `state.json` 的 SHA-256 与源实例一致；
  - 审计 `backup.created` 4 条、`backup.restored` 6 条（含拒绝）。
- `cargo test`：26 项全部通过（新增 3 项备份测试：回环恢复、篡改拒绝不动现场、清单路径穿越拒绝）。

## 已知差距（照原样保留，并补充本版边界）

- **恢复不是跨文件事务**：`config/` 与 `state/` 下的文件无法作为一个整体原子替换。正常写入失败会按逆序自动回滚；但若进程在恢复过程中被强制杀死，仍可能留下部分文件已替换的状态，需要从 `prerestore-*` 快照人工恢复。
- **恢复后必须重启**：文件已替换，但运行进程内存中的配置仍是旧值；界面会明确提示重启生效。
- **备份不含审计日志**：审计只追加，不参与覆盖式恢复（这是有意选择，不是遗漏）。
- **更新流程未实跑**：审计对更新链路的覆盖只做了代码接线，没有在本轮用真实更新流程逐条核对审计事件。
- **`export.download` 成功路径未实测**：只验证了拒绝路径（校验 FAIL 时写 `denied`），成功下载的审计记录没有实跑确认。
- **日志页筛选未在真实浏览器点验**：筛选与 CSV 导出只做了接口与语法检查，没有在浏览器里逐项点击验证。
- **HTTPS 的 Windows 权限**：私钥 0600 是 Unix 权限位，Windows 上不生效。
- **TLS 变更需重启**：证书、私钥、明文策略变更后需重启进程生效。
- **没有 ACME**：只支持手动 PEM 或自签。
- **`strict` 返回 403**：不做 HTTP → HTTPS 跳转。
- **入站与客户端编辑范围有限**：入站只改备注/监听/端口/启用；客户端只改 email/配额/到期/启用/flow，协议与安全层不可改。
- **没有退出登录按钮**：`POST /api/auth/logout` 可用，但界面未放入口，需清 Cookie 或等会话过期。
- **空白默认值**：明文策略默认 `warn`，升级后行为不变；切 `loopback-only` / `strict` 需在设置页选择后保存并重启。

## 升级

从 `1.0.3-alpha2`：设置页「检查更新」→「更新」→ 下载 → 校验签名 → 替换 → 自动重启。明文策略仍默认 `warn`，升级后行为不变。
