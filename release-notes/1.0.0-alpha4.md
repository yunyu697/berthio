# Berthio 1.0.0-alpha4

M4：3x-ui 只读迁移 + 订阅链路完善。**alpha 版本，未签名，不建议生产使用。**

## 本版内容

### 1. 3x-ui / x-ui 只读迁移

- **绝不写源库**：整个流程对源库只做读取。源库无 `-wal/-shm` 时用 `SQLITE_OPEN_READ_ONLY` 连接 + `VACUUM INTO` 生成事务级快照；存在 `-wal/-shm` 时**连只读连接都不打开**，直接拷贝 `db + -wal` 到 Berthio 自己的 `tmp/migrate/`，再对副本做 `integrity_check`。任何路径都不执行 `UPDATE/INSERT/DELETE`，也不打开可写句柄。
- **一致性证据**：预览返回源库抓取前后的 SHA-256（`source.sha256` / `source.sha256_after_capture`）、WAL 字节数、`integrity_check` 结果、快照策略（`vacuum_into_readonly` / `file_copy`）与并发写提示。源库哈希前后变化会明确标注「存在并发写入」。
- **面板运行中的风险说明**：检测到 `-wal` 时返回「文件拷贝不是事务级快照，若拷贝期间正好提交可能得到撕裂页，已用 integrity_check 拦截；需要严格一致性请先停面板，本工具不会替你停进程」。本工具不停止、不启动、不配置对方面板。
- **schema 识别**：读取 `sqlite_master` + `PRAGMA table_info(inbounds)`，校验必需列后判定 `3x-ui v3.x` / `3x-ui v2.x` / `x-ui（旧版）`；缺少 `inbounds` 或必需列返回 422 `unsupported_database`（PostgreSQL 后端不支持）。版本差异与字段来源以 3x-ui v2.9.4、vaxilu/x-ui 源码为准（见 `MIGRATION-3XUI.md`）。
- **单位实测**：`settings.clients[].totalGB` 库里实际是**字节**（源码写入前乘 `1024^3`）；`expiryTime` 是**毫秒**时间戳（0 = 不限期，负数按 0 处理）。
- **Reality 实测修正**：3x-ui v2.9.4 的 `privateKey` 在 `realitySettings` **顶层**，`publicKey` 在 `realitySettings.settings.publicKey`；`xray -test` 只给 privateKey 通过（exit=0），只给 publicKey 失败（exit=23）。因此 privateKey/publicKey 缺一都判冲突。
- **可继承 / 不可继承**（预览响应 `mapping_notes` 同步返回）：
  - 可继承：remark/tag/listen/port/enabled、VLESS 的 network/security、客户端 uuid/email/flow/limitIp/配额/到期/启用、Reality 全套参数。
  - 不可继承：TLS 证书文件本体（只记录源路径）、inbound 级流量与到期/重置策略、sniffing、fallbacks、externalProxy、sockopt、客户端 subId/tgId/comment/reset、在线状态。
- **协议范围**：本轮只导入 VLESS（tcp/ws/xhttp + tls/reality）。vmess/trojan/shadowsocks/hysteria/tuic 明确跳过并给出原因，不用「能读出来」冒充「导入后能订阅」。
- **先预览后落地**：`POST /api/migrate/preview` 返回 `preview_id` / `plan_hash` / `counts`（import/skip/conflict/already_imported）/ 逐条 `items`（含原因、警告、冲突处理建议）与 `readonly_guarantee`。`POST /api/migrate/apply` 必须同时提交 `preview_id + plan_hash + confirm=true`，否则 400；数据变化导致 plan 不符返回 409 `plan_changed` 且不写入。
- **幂等**：`source_ref = 3xui:<源路径指纹>:<源 inbound id>`。重复 apply 按 `source_ref` 跳过已导入项，不产生重复入站；重复预览显示 `already_imported`。
- **冲突处理建议**：预览对 Reality 缺密钥、同端口重复、tag 已被 Berthio 占用、fallbacks 非空、ws path≠`/`、端口非法、客户端缺 UUID/email 重复等给出具体原因与建议；apply 写锁内二次检查 tag/端口。

### 2. 订阅链路

- **地址**：`GET /sub/<token>?target=mihomo|sing-box`；`clash` / `clash-verge` / `clash.meta` / `stash` 归一化为 `mihomo`，`singbox` / `sfa` / `sfi` / `sft` 归一化为 `sing-box`；其它值 400。
- **token 模型**：每个客户端独立 token（`bto_` + 48 hex），明文只在创建/轮换响应里返回一次，服务端只存 SHA-256；可轮换（旧 token 立即失效）、可吊销（吊销是终态，不能轮换）；客户端停用后订阅返回 403 `client_disabled`。
- **错误语义**：缺失/无效/已被轮换 → 401 `subscription_unauthorized`（不区分「格式对但不存在」，避免枚举）；已吊销 → 403 `revoked`；非法 target → 400。
- **target 选择**：显式 `?target=` 优先；否则按 User-Agent 推断（含 `sing-box`/`sfa`/`sfi` → sing-box，含 `mihomo`/`clash`/`stash`/`verge` → mihomo）；再回退 token 记录的默认 target，最后 mihomo。
- **下发门槛**：渲染后 L0/L1 任一 FAIL 返回 422 `subscription_blocked`（带 `render_id`、`validation` 与首个失败原因 `detail`），审计 `sub.blocked`；成功审计 `sub.access`。
- **响应头**：`X-Berthio-Render-Id` / `X-Berthio-Target` / `X-Berthio-Validation` / `X-Berthio-Warnings`，`Cache-Control: no-store`。
- **令牌泄露影响范围**：拿到 token 的人只能读取该**单个客户端**的订阅配置（节点地址、端口、UUID、Reality publicKey 等公开连接参数），不能管理面板、不能读取其它客户端、不能触发写操作；所有 `/api/*` 仍需登录会话与 CSRF。最小权限做法：每客户端单独发放、不共用 token、怀疑泄露立即轮换（旧链接立刻 401）；确认泄露且不再使用时吊销。
- **前端**：只接上设计稿已有的 token「轮换 / 吊销」按钮，未改版式。

## 实测结果（Windows 10/11，真实二进制）

迁移用自造 3x-ui v2.9.4 结构样本库（`scripts/make-3xui-fixture.py`），不碰任何真实机器：

| 项目 | 结果 |
|---|---|
| v2.9.4 样本（12 条源入站） | 预览：**导入 3 / 跳过 5 / 冲突 4**；`source_rows=12` |
| 导入 3 条原因 | `jp-reality`（Reality，2 客户端）、`sg-tls`（TLS+WS）、`paused-reality`（源端停用，状态一并继承） |
| 跳过 5 条原因 | trojan（导出器未实现）、`security=none`、未知协议 `foobar`、无客户端、gRPC 传输 |
| 冲突 4 条原因 | Reality 缺 privateKey（只认 publicKey 而不能启动）、同库端口 443 重复、fallbacks 非空、WS 自定义 path `/custom` |
| 只读保证 | 预览/apply 后 `v2.db` 哈希与抓取前逐字节一致；旧版 `old.db`、WAL 样本 `v2-wal.db` 及 `-wal` 均未变 |
| WAL 样本（模拟面板运行中） | 策略为 `file_copy`，未打开源库；`integrity_check=ok`；导入 1 条 Reality |
| 旧版 x-ui 样本 | 2 条：导入 1 / 跳过 1（无 `client_traffics`，已用流量按 0 并给警告） |
| 确认机制 | 不带 `confirm=true` → 400；`plan_hash` 不符 → 409，入站仍为 0；确认后导入 3 条 |
| 幂等 | 重复预览 `import=0 / already_imported=3`；重复 apply `imported=0`，入站总数仍为 3 |
| tag 冲突 | 现网已有同名 tag 的样本库：预览判冲突并说明占用者，apply 不写入 |
| 订阅 401/403 | 缺 token → 401；随机无效 token → 401；轮换后旧 token → 401；吊销后 → 403 `revoked`；吊销后再轮换 → 409 |
| 订阅内容 | mihomo 输出含 Reality publicKey、面板地址、客户端 UUID；sing-box 输出含 publicKey 与 UUID |
| 订阅校验 | 服务端响应 L0/L1 = PASS；脚本把**同一响应体**落盘后用真实二进制复检 |
| mihomo 真实校验 | `mihomo 1.19.33 -t -f` → **exit=0** |
| sing-box 真实校验 | `sing-box 1.14.4 check -c` → **exit=0** |
| xray Reality 坑 | 只给 privateKey `xray -test` → **exit=0**；只给 publicKey → **exit=23** |
| token 存储 | `state.json` 不含 token 明文，仅存 `token_hash`；轮换只替换 hash |
| 回归 | M2 镜像换源 14 项全过；M3 鉴权 29 项全过；M3 内核 25 项全过；`cargo test` 3 项全过；M4 脚本全部断言 **0 失败** |

## 未验证 / 已知限制

- **3x-ui v3.x 真实库未实测**：`exclude_from_sub` / `origin_node_guid` / `disable_flow` 的版本判定来自 v3 源码结构，本轮只有 v2.9.4 与旧版 x-ui 样本，v3 分支标为**未验证**。
- **面板运行中的真实并发写未实测**：WAL 场景用「预置 `-wal/-shm` 的样本库」模拟，验证了不打开源库与 `integrity_check` 路径；未在真实运行中的 3x-ui 面板上边写边迁移，因此「撕裂页」只在代码层拦截，未制造出真实撕裂样本。
- **PostgreSQL 后端不支持**：3x-ui 的 PG 模式没有 SQLite 文件可读，直接 422，不做推断式迁移。
- **证书文件本体不迁移**：TLS 入站只继承证书路径字符串；路径不存在或权限不足时需用户自行补证书，工具不改文件系统。
- **inbound 级统计不迁移**：只迁移客户端级 `client_traffics`（抓取时点快照）；入站 `up/down/total/expiry_time` 只用于预览提示，不写入。
- **xhttp 客户端支持未验证**：xhttp 入站会导入并附风险提示，但目标客户端（mihomo/sing-box 具体版本）是否支持未逐一实测。
- **L2 未在服务端逐次强制**：服务端 L2 依赖本机内核二进制；本轮的真实 `mihomo -t` / `sing-box check -c` 是脚本对同一响应体复检，不是每次订阅请求都强制跑二进制。
- **UA 推断只覆盖已知客户端标识**：未覆盖全部第三方客户端；未知 UA 回退 token 记录的 target。
- **旧版 x-ui 仅覆盖一种 schema**：极老版本字段差异未穷举，缺必需列会明确 422。
- **32 位 / Linux 迁移路径未实测**：本轮实机为 Windows；`rusqlite` 使用 bundled sqlite，Windows/Linux 行为一致，但 Linux 只读快照未实机验证。
- 本 alpha 未签名；发布附件为 Linux 构建，Windows 下请按脚本自测。

## 与上一版的关系
