# Berthio 1.0.0

首个正式版。目标不变：用一个单文件面板替代 3x-ui 的入站/客户端/订阅/用量管理，配置生成由 xray / sing-box / mihomo 真实验证后才下发。

## 本版重点

1. **3x-ui 入站 JSON 导入（主路径）**：粘贴或上传 3x-ui 的入站 JSON，自动识别单条对象 / `inbounds` 数组 / 整份备份（含 `xray`、`obj` 套层），`settings` / `streamSettings` / `sniffing` 的**对象与字符串化 JSON 两种形态都支持**。先预览后落地，显示导入 / 跳过 / 冲突条数与逐条原因；幂等（同 remark/端口/uuid 重复导入不会产生重复入站）；非法 JSON 定位到「第 N 行第 M 列」，缺字段定位到「第 N 条 + 字段 + 原文片段」。
2. **数据库路径降为批量兜底**：只读打开 `x-ui.db`（必要时连 `-wal` 一起快照到 `tmp/` 并 `VACUUM INTO`），读完立即删除快照，源库 SHA-256 / 权限 / 大小前后不变。
3. **补齐 alpha4 未验证项**：3x-ui v3.11.0 真实库实测、Linux 迁移实跑、xhttp 客户端矩阵、REALITY 端到端、L2 运行期门禁。
4. **升级路径**：`state.json` / `panel.json` 的 `schema_version` 升到 2，alpha4（v1）启动时自动迁移，迁移前逐字节备份，校验失败自动回滚，高版本拒绝启动不改写。
5. **稳定性**：30 分钟以上持续压测（CPU/内存曲线、日志轮转、并发订阅、内核异常退出自动拉起、面板重启接管），无异常退出与泄漏。

## 支持矩阵

| 能力 | 支持情况 | 实测版本 / 备注 |
|---|---|---|
| 服务端内核 | xray、sing-box | xray **25.6.8**、sing-box **1.14.4**（`check` 实测） |
| 入站（xray） | VLESS + REALITY / TLS，传输 tcp、ws、xhttp | REALITY 端到端用 xray 客户端实测通过 |
| 入站（sing-box） | VLESS、hysteria2、tuic | Reality 经 `sing-box check`；**hysteria2 无真实样本，未验证** |
| 客户端配置导出 | Clash / mihomo YAML、sing-box JSON | mihomo **1.19.33**（`-t` 实测）、sing-box **1.14.4**（`check -c` 实测） |
| xhttp 传输 | **仅 xray 客户端** | xray 25.6.8 真实连接成功；sing-box 1.14.4 拒绝 `unknown transport type: xhttp`；mihomo 1.19.33 语法通过但真实连接失败 → 导出时运行期剔除并告警 |
| 3x-ui 导入 | DB（v2.9.4 风格 / v3.11.0）与 JSON 三条入口 | 同一样本均为 **3 导入 / 3 跳过 / 2 冲突**，Windows 与 Linux 一致 |
| 校验门禁 | L0 结构 / L1 语义 / L2 二进制自检 | **运行期逐请求**执行；L2 FAIL 直接拒绝下发（422） |
| 更新检查 | 本轮不含新交互（见「已知限制」） | — |

### xhttp 实测边界

| 客户端 | 语法检查 | 真实连接 | 结论 |
|---|---|---|---|
| xray 25.6.8 | 通过 | **成功** | 可用 |
| sing-box 1.14.4 | 拒绝（`unknown transport type: xhttp`） | 未进入连接 | 不可用 |
| mihomo 1.19.33 | `-t` 通过 | 失败（TLS handshake EOF） | 不可用 |

## 安装

### Linux（x86_64，glibc 2.36+ / Debian 12 基线）

```bash
chmod +x berthio-1.0.0-linux-x86_64
BERTHIO_HOME=/opt/berthio ./berthio-1.0.0-linux-x86_64
# 面板默认监听 127.0.0.1:18080；首次打开 http://127.0.0.1:18080 设置口令
```

### Windows（x86_64）

```powershell
.\berthio-1.0.0-windows-x86_64.exe
# 数据目录默认 .\.berthio（存在 C:\opt\berthio 时优先），可用 BERTHIO_HOME 覆盖
```

### 演示

```bash
./berthio --demo          # 127.0.0.1:18090，临时状态、内置演示数据、不启动真实内核
```

也可直接打开附件里的 `berthio-1.0.0-demo-m5.html`（离线演示页）。

环境变量：`BERTHIO_HOME`（数据目录）、`BERTHIO_LISTEN`（覆盖监听地址）、`BERTHIO_DEMO_PORT`、`BERTHIO_KERNEL_DIR`（外部内核目录）。
面板默认只监听回环；对外开放必须自行加 HTTPS/反代与强口令（启动时会打印安全提示）。

## 从 alpha4 升级

1. 停止旧进程，保留 `state/` 与 `panel.json`。
2. 启动 1.0.0：自动把 schema v1 迁到 v2（订阅 `target` 别名归一、入站 `source` 补齐、面板监听/日志天数/信任代理规范化），原文件备份到 `state/backups/`，日志打印 `schema 升级：…`。
3. 迁移失败会从备份回滚并拒绝启动，不会留下半迁移状态；`schema_version` 高于当前版本时拒绝启动且不改写文件。
4. 回滚：停 1.0.0，把 `state/backups/<kind>-<stamp>.json` 覆盖回原文件，再启动 alpha4。

## 稳定性（soak）

`scripts/test-m5-soak.ps1`，连续 **35 分钟**（每 5 秒采样，共 408 个样本），真实 xray 内核在跑，每 60 秒 6 路并发订阅：

| 指标 | 结果 |
|---|---|
| 面板 CPU | 平均 **0.17%**（单核基准），峰值 1.25% |
| 内核 CPU | 平均 0.01% |
| 面板内存 | 9.7–11.7 MB，均值 11.1 MB，线性趋势 **-0.06 MB/10min**（无泄漏） |
| healthz | 最大 19 ms，0 次失败 |
| 并发订阅 | 204 次请求全部 200，内容哈希一致（0 次错乱/错配置） |
| 日志轮转 | 2 轮，每份 1.35 MB 旧日志正确滚到 `.log.1` / `.log.2` |
| 内核异常退出 | `kill` 后自动拉起（PID 16388 → 61268，restarts=1），配置 SHA 与稳定态一致，订阅立即恢复 |
| 面板重启 | 重启后接管已有内核（PID 不变，`adopted=true`），入站与订阅状态完整 |
| 审计 | `kernel.auto_restart` / `kernel.adopted` / `sub.access` 均有记录 |

soak 中发现并修复的两个问题：
- `/api/kernels` 每请求都对三个内核二进制（约 190 MB）重算 SHA-256 并执行 `--version`，单请求 20s+ → 改为按 `mtime + 文件长度` 缓存，之后 < 100 ms。
- 测试脚本 `Start-Process` 未带 `-NoNewWindow` 会新建控制台（Windows 11 下表现为 Windows Terminal 窗口并抢前台）→ 全部脚本改为 `-NoNewWindow` + 输出重定向，整轮 soak 无任何可见窗口。

原始数据：`samples.csv` / `bursts.csv` / `summary.json`（随本轮验收记录留存，不入库）。

## 已知限制

- **xhttp 只有 xray 客户端可用**；含 xhttp 的入站导出给 mihomo/sing-box 会被运行期剔除（全被剔除则 L0 FAIL），不要把它当成全客户端能力。
- **hysteria2 入站未经真实样本验证**（本轮无可用样本），不要在生产上直接依赖。
- **mihomo 普通 Reality 的端到端连接未单独复测**；本轮 REALITY 端到端用的是 xray 25.6.8 客户端。
- 面板**不带内置 HTTPS**：默认只监听 `127.0.0.1`；对外必须反代 + HTTPS + 强口令。
- 单实例、单数据目录；不做集群/多机同步。
- 面板「检查更新」交互按 Renomio 方案列入 1.1 验收项，**本版未实现**（设置页暂无自动更新）。
